## 2. 通信协议差异

### 2.1 文档要求

- **协议**: SOAP 1.1 / SOAP 1.2
- **编码**: UTF-8
- **命名空间**: `http://monitor.rrmp.gov.cn/services/`
- **WSDL地址**: `http://{host}:{port}/services?wsdl`

### 2.2 实际实现（2026-04-06 已修复）

- **协议**: ✅ SOAP 1.1 + XML (Proxy→Atom)
- **编码**: UTF-8
- **命名空间**: `http://monitor.rrmp.gov.cn/services/`
- **Content-Type**: text/xml
- **端点**: `POST /services`

### 2.3 修复后的数据流

```
修复前:
  Client ──SOAP──▶ Proxy ──JSON──▶ Atom

修复后（符合文档）:
  Client ──SOAP──▶ Proxy ──SOAP──▶ Atom
```

### 2.4 修复内容（2026-04-06）

| 文件 | 修改内容 |
|------|---------|
| `main_atom.py` | 新增 `/services` SOAP端点，解析SOAP请求并分发到业务处理 |
| `app/proxy_service/routes.py` | `dispatch_to_atom_service()` 改为构建SOAP请求并发送 |

### 2.5 验证结果

- ✅ Atom服务的 `/services` SOAP端点正常工作
- ✅ Proxy→Atom使用SOAP/XML协议通信
- ✅ 响应数据正确解析并返回
- ✅ 集成测试全部通过

## 7. 数据流模式差异

### 7.1 文档要求

```
客户端 ──▶ 订阅请求 ──▶ 代理服务 ──▶ 原子服务 ──▶ 设备
     ▲                    │
     │                    ▼
     │              Stream推送
     │                    │
     └────────────────────┘
         实时数据流
```

### 7.2 实际实现

- **请求/响应模式**: 客户端发送请求 → 服务端返回响应
- **无Stream推送**: 不支持服务端主动推送
- **聚合页面**: 使用轮询(setInterval)模拟实时更新

### 7.3 用户说明

> 推送功能不需要现在实现，现在是验证阶段

## 8. 周期性交互说明

### 8.1 文档中的周期性机制

| 机制 | 配置值 | 说明 |
|------|--------|------|
| heartbeatInterval | 30000ms | 设备心跳保持连接 |
| 连接模式 | 短连接 | 每执行一功能均单独建立连接 |

### 8.2 实际实现

| 机制 | 实现状态 | 说明 |
|------|---------|------|
| 设备心跳 | ❌ 未实现 | 无心跳线程 |
| 连接保活 | ⚠️ 部分 | 仅在请求处理期间保持 |
| 周期性上报 | ❌ 无 | Mock设备为被动响应模式 |

### 8.3 用户说明

> 如果真实设备有周期上报，那么Mock设备也要做同样的功能

**需要确认**: 真实设备的周期性上报是哪种模式？
1. **心跳保活**: 定期发送心跳包维持连接（30秒间隔）
2. **数据主动上报**: 无请求情况下设备主动上报监测数据
3. **通知消息**: 设备异常/告警时主动通知
