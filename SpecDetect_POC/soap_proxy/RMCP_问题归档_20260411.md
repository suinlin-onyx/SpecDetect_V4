### 1. CheckSum 校验算法

| 项目       | 内容                                  |
| -------- | ----------------------------------- |
| **状态**   | ✅ **已解决**                           |
| **算法来源** | 协议文档 `无线电管理综合平台.通信协议v2.0_通用协议.html` |

#### 算法实现

```python
def _calculate_checksum(header: bytes) -> int:
    """
    RMCP 帧头校验和算法:
    1. length + timestamp (64位)
    2. 第一次折半移位: 高32位 + 低32位
    3. 第二次折半移位: 高16位 + 低16位 (循环直到 <= 0xFFFF)
    4. 取反码 (~result)
    """
    length = struct.unpack('<I', header[0:4])[0]
    timestamp = struct.unpack('<Q', header[4:12])[0]

    total = timestamp + length

    # 第一次折半移位
    high = (total >> 32) & 0xFFFFFFFF
    low = total & 0xFFFFFFFF
    result1 = high + low

    # 第二次折半移位 (循环处理溢出)
    result2 = (result1 >> 16) + (result1 & 0xFFFF)
    while result2 > 0xFFFF:
        result2 = ((result2 >> 16) & 0xFFFF) + (result2 & 0xFFFF)

    # 取反码
    return (~result2) & 0xFFFF
```

## 三、FILETIME 深入说明

### 1. FILETIME 定义

```
FILETIME: 从 1601-01-01 00:00:00 UTC 开始的 100纳秒间隔数
格式: 8字节 little-endian uint64
```

### 2. FILETIME 生成公式

```python
def _create_filetime(self) -> bytes:
    """创建当前 UTC 时间的 FILETIME"""
    now_utc = datetime.now(timezone.utc)
    ft_epoch = datetime(1601, 1, 1, tzinfo=timezone.utc)
    ft_value = int((now_utc - ft_epoch) / timedelta(microseconds=1)) * 10
    return struct.pack('<Q', ft_value)
```

### 3. 验证示例

| 项目        | 值                     |
| --------- | --------------------- |
| 当前 UTC 时间 | 2026-04-11 15:32:28   |
| 生成字节      | `d845dc67c8c9dc01`    |
| 反向转换      | 2026-04-11 15:32:28 ✓ |
| 时间误差      | < 1秒                  |

### 4. 时区说明

| 时区          | 说明                                         |
| ----------- | ------------------------------------------ |
| FILETIME 存储 | **UTC 时间** (无时区概念)                         |
| 北京时间显示      | UTC + 8小时                                  |
| **注意**      | 北京时间显示可能出现跨日现象 (如 UTC 23:00 = 北京 07:00 次日) |

### 5. bytes 8-11 "魔数" 的真相

最初发现的 `03CADC01` → `04CADC01` 递增现象：

| capture 文件 | bytes 8-11 | 解释                        |
| ---------- | ---------- | ------------------------- |
| 223719     | `03cadc01` | FILETIME 高4字节，时间较早在 22:40 |
| 224043     | `04cadc01` | FILETIME 高4字节，时间较晚在 22:50 |

**结论**：不是会话计数器递增，是时间自然增长导致的 FILETIME 变化。

## 四、重要说明

### 1. 帧头结构 (实测验证)

| 位置      | 字段        | 说明                                    |
| ------- | --------- | ------------------------------------- |
| [0-3]   | dwLength  | 帧长度 (little-endian)                   |
| [4-11]  | tmStamp   | **FILETIME** (8字节 UTC 时间)             |
| [12]    | 0x00      | 固定                                    |
| [13]    | nVersion  | 版本号 (=7)                              |
| [14]    | nMsgType  | 消息类型 (90=REQUEST, 6=RESPONSE, 0=DATA) |
| [15]    | nFlags    | 标志 (=1)                               |
| [16-17] | nCheckSum | 校验和 (待逆向)                             |
| [18+]   | XML       | SOAP XML (GB2312 编码)                  |

### 2. 文件命名约定

| 文件类型           | 扩展名    | 说明                      |
| -------------- | ------ | ----------------------- |
| Predicted RMCP | `.bin` | soap_proxy 预测生成的 RMCP 帧 |
| Actual RMCP    | `.raw` | rmcp_proxy 捕获的实际 RMCP 帧 |

### 3. 数据流说明

```
TestTool (SOAP)
    ↓
soap_proxy (记录 SOAP → 生成 Predicted RMCP)
    ↓
Atom (SOAP → Action 转换)
    ↓
Device
    ↑
    └── rmcp_proxy 透明监听 (捕获 Atom → Device 的实际 RMCP)
```

**注意**: Predicted RMCP 和 Actual RMCP 不应直接对比二进制，因为：

- 时间戳必然不同
- CheckSum 必然不同
- XML 格式不同 (SOAP vs Action)

**正确的对比方式**: 提取并对比业务参数

### funcid 推断逻辑

```python
def _infer_funcid(self, action_items, is_nil, has_taskid):
    # 1. xsi:nil + taskid -> B_StopMeas (32)
    if is_nil:
        return 32 if has_taskid else 10

    # 2. frequency+dfmode -> B_SglFreqDF (11)
    # 3. frequency -> B_SglFreqMeas (12)
    # 4. startfreq+stopfreq+step+dfmode -> B_FScanDF (21)
    # 5. startfreq+stopfreq+step -> B_FScan (15)
    # 6. startfreq+stopfreq -> B_WBDF (17)
    # 7. startfreq/stopfreq -> B_PScan (13)
```
