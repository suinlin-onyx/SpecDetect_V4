# RMCP Proxy 持久化文件说明

本文档说明 RMCP Proxy 捕获流量的三种持久化文件格式及其关系。

---

## 一、三种文件格式

### 1. `.raw` 文件 - 原始二进制数据

**文件命名**：`capture_YYYYMMDD_HHMMSS.raw`

**内容**：TCP 流量的完整二进制数据，按时间顺序存储所有发送/接收的字节。

**格式**：
```
[TCP数据包1完整内容][TCP数据包2完整内容][TCP数据包3完整内容]...
```

**特点**：
- 保留了最完整的信息，可用于事后完整分析
- 占用空间最小（纯二进制）
- 可用 Wireshark 直接打开分析

### 2. `.json` 文件 - 结构化JSON

**文件命名**：`capture_YYYYMMDD_HHMMSS.json`

**内容**：每帧的结构化信息，JSON数组格式。

**格式**：
```json
[
  {
    "timestamp": "2026-04-10 18:44:44.549",
    "direction": "C->S",
    "src": "127.0.0.1",
    "src_port": 1800,
    "size": 754,
    "hex": "f2020000...",
    "header": {
      "dwLength": 754,
      "nVersion": 7,
      "nMsgType": 90,
      "nMsgTypeName": "REQUEST",
      "nFlags": 1,
      "nCheckSum": 21156,
      "timestamp": "2026-04-11 02:44:44.546"
    },
    "data_type": "XML_REQUEST",
    "xml_content": "<?xml version=\"1.0\" encoding=\"gb2312\" ?>..."
  },
  ...
]
```

**特点**：
- 便于程序读取和处理
- 包含解析后的帧头信息和XML内容
- 可用于数据分析和可视化

### 3. `.log` 文件 - 文本日志

**文件命名**：`capture_YYYYMMDD_HHMMSS.log`

**内容**：人类可读的文本格式日志。

**格式**：
```
================================================================================
RMCP Traffic Capture Log
Started: 2026-04-10 18:44:37
================================================================================

Time: 2026-04-10 18:44:44.549
Direction: C->S
Source: 127.0.0.1:1800
Size: 754 bytes
Frame Header:
  dwLength: 754
  nVersion: 7
  nMsgType: 90 (REQUEST)
  nFlags: 0x01
  nCheckSum: 21156
  FrameTime: 2026-04-11 02:44:44.546

XML Content:
<?xml version="1.0" encoding="gb2312" ?>
<action id="1">
...

--------------------------------------------------------------------------------
```

**特点**：
- 人类可读，便于快速查看
- 适合调试和问题排查
- 可直接用文本编辑器打开

## 二、三种文件的关系

```
┌─────────────────────────────────────────────────────────────────┐
│                      TCP 流量捕获                                │
│                    (所有 C->S 和 S->C 数据)                      │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
        ▼                     ▼                     ▼
   ┌─────────┐          ┌─────────┐          ┌─────────┐
   │  .raw   │          │  .json  │          │  .log   │
   │  二进制 │          │  JSON   │          │  文本   │
   └─────────┘          └─────────┘          └─────────┘
        │                     │                     │
        ▼                     ▼                     ▼
   Wireshark打开      程序解析处理        人类阅读
   完整流量分析       数据结构化          快速查看
```

**同步关系**：
- 三种文件同时生成，捕获同一时间段的数据
- `.raw` 是最底层的数据，其他两种是对 `.raw` 的不同形式的解读
- 可以用 `.raw` 重新生成 `.json` 和 `.log`

**字段对应**：

| .raw | .json | .log |
|------|-------|------|
| 原始字节流 | `hex` 字段 | 十六进制显示 |
| 无帧头解析 | `header` 对象 | 帧头各字段 |
| 无数据类型 | `data_type`, `xml_content` | XML内容 |

## 三、.raw 文件的解析方式与工具

### 1. Wireshark（推荐）

Wireshark 可直接打开 `.raw` 文件进行分析。

**使用方法**：
1. Wireshark 菜单：`File -> Open` 选择 `.raw` 文件
2. 或命令行：`wireshark capture_20260410_184437.raw`

**显示过滤器示例**：
```
tcp.port == 9997              // 仅显示9997端口流量
tcp.port == 9999              // 仅显示9999端口流量
ip.src == 127.0.0.1           // 仅显示来自代理的流量
ip.src == 172.18.114.231      // 仅显示来自设备的流量
```

**注意**：Wireshark 会将 `.raw` 当作 TCP 流量解析，可能需要设置：
- `Analyze -> Decode As` 将端口配置为 TCP
- 或使用 `tcpdump -r capture.raw` 命令行查看

### 2. tcpdump 命令行工具

```bash
# 查看原始数据包列表
tcpdump -r capture_20260410_184437.raw -n

# 仅显示TCP流量
tcpdump -r capture_20260410_184437.raw -n tcp

# 仅显示特定端口
tcpdump -r capture_20260410_184437.raw -n port 9997

# 保存过滤后的流量
tcpdump -r capture.raw -w filtered.raw port 9997
```

### 3. Python 脚本解析

使用 Python 读取和解析 `.raw` 文件：

```python
import struct
import json

RMCP_FRAME_HEADER_SIZE = 18

def parse_rmcp_frame(data):
    """解析RMCP帧头"""
    if len(data) < RMCP_FRAME_HEADER_SIZE:
        return None

    dwLength = struct.unpack('<I', data[0:4])[0]
    tmStamp = struct.unpack('<Q', data[4:12])[0]
    nVersion = struct.unpack('>H', data[12:14])[0]  # 大端序
    nMsgType = data[14]
    nFlags = data[15]
    nCheckSum = struct.unpack('<H', data[16:18])[0]

    return {
        'dwLength': dwLength,
        'tmStamp': tmStamp,
        'nVersion': nVersion,
        'nMsgType': nMsgType,
        'nFlags': nFlags,
        'nCheckSum': nCheckSum
    }

def read_raw_file(filepath):
    """读取.raw文件并解析"""
    with open(filepath, 'rb') as f:
        data = f.read()

    # 尝试按帧解析
    offset = 0
    frames = []
    while offset < len(data):
        # 读取帧头获取长度
        if offset + 4 > len(data):
            break
        dwLength = struct.unpack('<I', data[offset:offset+4])[0]

        frame_size = 18 + dwLength  # 帧头 + 数据载荷
        if offset + frame_size > len(data):
            # 数据不完整，尝试寻找下一个有效帧
            offset += 1
            continue

        frame_data = data[offset:offset+frame_size]
        header = parse_rmcp_frame(frame_data)

        frames.append({
            'offset': offset,
            'size': frame_size,
            'hex': frame_data.hex(),
            'header': header
        })

        offset += frame_size

    return frames

# 使用示例
frames = read_raw_file('capture_20260410_184437.raw')
print(f"共解析 {len(frames)} 帧")
```

## 四、文件恢复

如果需要从 `.raw` 文件恢复完整的捕获记录：

```python
import struct
import json
from datetime import datetime

RMCP_FRAME_HEADER_SIZE = 18
MSG_TYPE_NAMES = {
    90: 'REQUEST',
    6: 'RESPONSE',
    29: 'DATA_29',
    95: 'DATA_95',
}

def reconstruct_json_from_raw(raw_path, output_json_path):
    """从.raw文件重建.json记录"""
    frames = read_raw_file(raw_path)

    records = []
    for frame in frames:
        header = frame['header']
        if header:
            record = {
                'timestamp': 'reconstructed',
                'direction': 'unknown',
                'size': frame['size'],
                'hex': frame['hex'],
                'header': {
                    'dwLength': header['dwLength'],
                    'nVersion': header['nVersion'],
                    'nMsgType': header['nMsgType'],
                    'nMsgTypeName': MSG_TYPE_NAMES.get(header['nMsgType'], f'UNKNOWN({header["nMsgType"]})'),
                    'nFlags': header['nFlags'],
                    'nCheckSum': header['nCheckSum']
                }
            }

            # 如果是REQUEST，尝试解析XML
            if header['nMsgType'] == 90:
                xml_data = frame['hex'][RMCP_FRAME_HEADER_SIZE*2:]  # 去掉帧头的hex
                try:
                    xml_bytes = bytes.fromhex(xml_data)
                    xml_start = xml_bytes.find(b'<?xml')
                    if xml_start >= 0:
                        record['xml_content'] = xml_bytes[xml_start:].decode('gb2312', errors='ignore')
                except:
                    pass

            records.append(record)

    with open(output_json_path, 'w', encoding='utf-8') as f:
        json.dump(records, f, ensure_ascii=False, indent=2)

    print(f"重建完成，共 {len(records)} 条记录")
```

## 五、文件大小参考

| 文件类型 | 大小估算公式 | 1000帧典型大小 |
|----------|-------------|----------------|
| .raw | ~帧平均大小 × 帧数 | ~500KB - 2MB |
| .json | ~帧平均大小 × 帧数 × 1.5 | ~1MB - 3MB |
| .log | ~每帧 ~200-500字节 × 帧数 | ~200KB - 500KB |

`.json` 文件最大，因为它存储了完整的十六进制字符串和解析后的字段。
