# RMCP Proxy 项目总结

## 项目状态
已完成

## 项目概述
- 目标: 监听AtomSvcV3.exe与设备172.18.114.231:9999的RMCP协议通信
- 代理端口: 9997
- 协议: RX-RMCPTP (Radio Monitoring and Control Protocol)

## 实现内容

### 1. RMCP帧解析器 (RMCPFrame)
- 18字节帧头解析
- 混合字节序: nVersion大端序，其他小端序
- FILETIME时间戳转换
- 帧头有效性验证(nVersion=7, 合理长度, 合理时间戳范围)

### 2. 流量记录器 (CaptureLogger)
- 原始二进制文件(.raw) - 可用Wireshark打开
- 结构化日志(.log)
- JSON格式记录(.json)
- 实时保存，每帧写入

### 3. TCP透明代理 (ProxyConnection)
- 双向转发: 客户端<->设备
- 独立线程处理两个方向
- 流量记录和帧解析
- 异常处理和资源清理

### 4. 启动脚本
- `start_atom.bat` - 启动代理+AtomSvcV3+RXAtomTestTool3
- `start_proxy.bat` - 仅启动代理

## 发现的问题与修复

### 问题1: 程序崩溃 - 连接断开时recv抛出异常
- **原因**: 设备发送RST断开连接时，recv()抛出ConnectionResetError
- **修复**: 添加ConnectionResetError/BrokenPipeError专门捕获

### 问题2: Ctrl+C无法退出
- **原因**: server.accept()阻塞，无法响应KeyboardInterrupt
- **修复**: 设置server.settimeout(1.0)，捕获TimeoutError

### 问题3: close()方法定义丢失
- **原因**: 编辑时缩进错误导致def close(self):成为浮动代码块
- **修复**: 恢复正确的缩进和def语句

### 问题4: 外层except:pass吞掉异常
- **原因**: bare except捕获所有异常包括系统异常但不打印
- **修复**: 改为traceback.print_exc()

### 问题5: 重复调用close()导致竞态
- **原因**: 两个转发线程都可能调用close()
- **修复**: 添加close_lock锁和running状态检查

### 问题6: 日志文件未实时保存
- **原因**: 只在程序退出时写入
- **修复**: 添加_save_json_line()和_save_log_line()每帧实时保存

## 要注意的坑

### 1. 设备返回非RMCP数据
- 设备可能返回RMTP错误消息(如"设备连接失败")
- 这些数据没有RMCP帧头，会被标记为RAW_DATA
- 61字节的`RMTP:ErrCode=-1`是设备主动发送的错误通知，不是RMCP帧

### 2. RMCP帧头字节序
- nVersion是大端序(Big Endian)
- 其他字段(dwLength, tmStamp, nMsgType, nFlags, nCheckSum)是小端序(Little Endian)
- 解析时必须注意: struct.unpack('<I') vs struct.unpack('>H')

### 3. FILETIME时间戳范围
- 有效范围: 1601-01-01到现在
- 转换公式: unix_time = (tmStamp - 116444736000000000) / 10000000
- 无效时间戳说明数据不是RMCP帧

### 4. XML编码
- 请求中的XML使用GB2312编码，不是UTF-8
- 解析时需要: xml_data.decode('gb2312', errors='ignore')

### 5. 设备配置修改
- 使用前需将设备配置中的serverip改为127.0.0.1，serverport改为9997
- 测试完成后记得改回原值(172.18.114.231:9999)
