# Atom与Device连接架构分析

> 创建日期：2026-04-06
> 用途：记录 Atom（客户端）与 Device（服务端）的连接架构讨论

---

## 一、协议规定的角色分工

### 1.1 原始协议描述（RMCPTP v2.0 第1.4节）

> "每个监测业务请求都需要客户端建立一个新的链接，并由客户端发起请求，中间服务端进行应答，业务处理完成后，双方断开本次链接。"
>
> "连接请求由客户端发起，客户端通过socket连接到中间服务端，每执行一功能，均单独建立一连接"

### 1.2 角色定义

| 协议角色 | 真实场景 | 说明 |
|---------|---------|------|
| 客户端 | Real Atom | 发起连接，发送请求命令 |
| 中间服务端 | Real Device | 被动监听Socket，响应请求 |

### 1.3 连接模式

- **短连接**：每执行一功能，单独建立一次TCP连接
- 客户端发起连接 → 发送请求 → 服务端应答 → 双方断开
- **非心跳模式**：协议中无心跳保活机制

### 1.4 通信链路

```
Real Atom（客户端） ←→ Socket(RX-RMCPTP) ←→ Device（服务端，USB驱动/virtual COM）
```

## 二、真实设备特性

- 设备以USB方式接入PC
- 设备驱动实现了"无线电协议2.0"
- **设备作为被动角色（服务端）**，等待客户端发起请求
- 不同品牌设备可能存在差异，需要记录

---

## 三、切换方案

### 3.1 目标

切换 Atom 实现（Our Atom ↔ Real Atom），其它组件维持原状：

```
[场景A] Proxy → Our Atom (main_atom.py) → Mock Device
[场景B] Proxy → Real Atom → Mock Device
```

### 3.2 切换影响范围

| 组件 | 变化 |
|------|------|
| Proxy → Atom | SOAP接口兼容，切换host:port即可 |
| Atom → Device | RMCPTP v2.0协议，Real Atom作为客户端连接Mock Device |

### 3.3 配置方式

- Proxy → Atom：在 settings.py 中配置 `SERVICES['atom']['host']` 和 `SERVICES['atom']['port']`
- 默认值：Mock Atom（`127.0.0.1:9090`）
- 不做持久化，每次重启回归默认

## 四、协议结构验证（RMCPTP v2.0）

### 4.1 帧头结构（18字节）— ✅ 已验证一致

| 字段 | C++类型 | 长度 | 实现 |
|------|---------|------|------|
| dwLength | DWORD | 4 | `!I` ✅ |
| tmStamp | FILETIME | 8 | `!Q` ✅ |
| nVersion | WORD | 2 | `!H` ✅ |
| nDataType | BYTE | 1 | `B` ✅ |
| nFlags | BYTE | 1 | `B` ✅ |
| nCheckSum | WORD | 2 | `!H` ✅ |

校验和算法：长度/时间累加 → 两次折半移位 → 取反码 ✅

### 4.2 业务数据头结构（11字节）— ✅ 已验证一致

```
nBdType(1) + nFlags(2) + nArrays(4) + nOffset(4) = 11字节
格式: !B H I I
```

### 4.3 关键业务类型字段验证

| 业务类型 | 协议定义 | 实现 | 状态 |
|---------|---------|------|------|
| SGLFREQ (0x10) | freq(8) + level(short×100) | freq(8) + itu_value(short×100) | ✅ 已修正 |
| IFANALYSIS (0x11) | freq(8) + level(short×100) | freq(8) + level(short×100) | ✅ |
| DF (0x12) | level+DfLevel(2+2) + Qulity+Azumith+Elevation+compass(4×4) | 同协议 | ✅ |
| IFDF (0x13) | 同DF结构 | 同协议 | ✅ |
