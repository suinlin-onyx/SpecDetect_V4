## 二、组件说明

| 组件 | IP:Port | 协议 | 职责 |
|------|---------|------|------|
| **TestTool3** | 动态端口 | SOAP / streamsrc | 发送SOAP请求，接收streamsrc频谱数据回调 |
| **SOAP Proxy** | 127.0.0.1:8082 | TCP (SOAP透传) | 透明转发SOAP请求，记录①④日志 |
| **Real Atom** | 127.0.0.1:8282 | SOAP / RMCPTP / streamsrc | SOAP服务端，内部完成SOAP→RMCPTP转换，streamsrc服务端 |
| **streamsrc** | 127.0.0.1:18012 | TCP (streamsrc) | Atom内部通道，将Device数据转发给TestTool |
| **rmcp_proxy** | 127.0.0.1:9996 | TCP (RMCPTP透传) | 抓取Atom↔Device的RMCPTP帧，记录②③日志 |
| **Real Device** | 100.72.95.36:1449 | RMCPTP | RMCPTP服务端，接收命令，返回频谱数据 |

## 三、数据流与匹配链路

### ① SOAP请求 → SOAP Proxy → Real Atom

```
TestTool3              SOAP Proxy (:8082)           Real Atom (:8282)
    │                         │                            │
    │──── SOAP请求 ──────────▶│──── SOAP请求(透传) ───────▶│
    │   POST /B_FScan         │    完全相同                │  ← Real Atom 内部完成
    │   taskid: xxx          │                            │    SOAP → RMCPTP 转换
    │   startfreq=137MHz     │                            │
    │   stopfreq=173MHz      │                            │
    │   step=25kHz           │                            │
    │                        │                            │
    │ timestamp: T_soap_req  │ timestamp: T_soap_req+δ1   │ timestamp: T_soap_req+δ1+δ2
```

**匹配条件**：
- SOAP Proxy 只做透明转发，内容完全一致
- Real Atom 内部将 SOAP 转换为 RMCPTP 帧

## 五、匹配算法流程

```
输入: SOAP日志目录, RMCPTP日志文件

1. 遍历SOAP请求目录:
   提取: uuid, operation, taskid, params{startfreq,stopfreq,step}, timestamp

2. 对于每个SOAP请求:
   a. 在RMCPTP日志中查找时间最接近的 nMsgType=90 请求帧
      条件: |rmcp_timestamp - soap_timestamp| < 500ms
            且 funcid匹配 (SOAP funcid=15 对应 RMCPTP funcid=15)
            且 params完全匹配

   b. 找到RMCPTP请求后,查找后续的 nMsgType=6 响应帧
      条件: 同一会话, 时间顺序

   c. 查找后续的 nMsgType=0 DATA帧序列
      条件: 时间顺序, params匹配

3. 输出匹配结果:
   {
     soap_uuid: xxx,
     soap_request: {...},
     soap_response: {...},
     rmcp_request: {timestamp, hex, funcid},
     rmcp_response: {timestamp, hex},
     rmcp_data_frames: [{timestamp, hex, parsed_data}, ...]
   }
```

## 六、关键说明

1. **协议转换点**：SOAP → RMCPTP 转换由 **Real Atom 内部**完成，SOAP Proxy 只做透明转发
2. **双通道数据**：SOAP响应只确认命令接收，实际频谱数据通过 **streamsrc 独立通道**推送
3. **日志时间差**：SOAP日志(17:12)与RMCPTP日志(14:14)存在时间差，需同时间段数据才能匹配
4. **streamsrc抓包**：目前无法直接抓取 streamsrc 数据回调，需额外方案

## 八、B_FScan DATA帧解析（2026-04-11 19:10 验证）

### 帧结构
| 字段 | 大小 | 说明 |
|------|------|------|
| RMCP Header | 16 bytes | 标准RMCPTP帧头 |
| Business Header | 17 bytes | nBdType(1) + nArrays(4) + nOffset(4) + ... |
| 频谱数据 | N*2 bytes | int16 little-endian, 每帧跳过前4个值 |

### 转换公式
```
dBm = raw_int16_value / 10
```

### 验证数据
- **rmcp_proxy捕获**: `capture_20260411_191028.json`
- **TestTool日志**: `test_tool_log/20260411_1910.txt`
- **验证结果**: 1441个数据点全部验证通过，误差 -0.2 ~ -0.9 dBm
