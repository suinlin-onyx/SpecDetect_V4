## ISSUE-001: Real Atom SOAP 处理崩溃

### 问题描述
Real Atom 收到 SOAP 请求后立即崩溃，产生 crash dump。

### 崩溃分析

**崩溃类型**: Access Violation (0xC0000005)
- 尝试从 **NULL 指针 (0x00000000)** 读取数据

**崩溃位置**: `0x7BCBB9F0`
- 发生在 AtomSvcV3.exe 处理请求时

**PDB 信息**: AtomSvcV3.pdb (存在于 dump 中)

### 根因分析
```
NULL pointer dereference
尝试读取地址 0x00000000
```

可能触发原因：
1. SOAP 请求中的 mfid/equid 无效或为空
2. 设备配置未正确加载到内存
3. gSOAP 解析 XML 时访问未初始化对象
4. 内部状态机处理请求时对象未正确初始化

## ISSUE-002: streamsrc 与 devinfo 配置关系

### 问题描述
不清楚 streamsrc 和 devinfo.station 的角色和关系。

### 配置对比

| 配置项 | YL_workspace (原始) | claude_workspace (修改后) |
|--------|-------------------|--------------------------|
| streamsrc ip | 172.18.114.166 | 127.0.0.1 |
| streamsrc port | (空) | 9000 |
| station serverip | 172.18.114.231 | 127.0.0.1 |
| station serverport | 9999 | 9000 |

### 分析结论

**Real Atom 的 streamsrc**：
- Real Atom 监听 streamsrc 端口（随机分配如 18012）
- 等待设备主动连接到 streamsrc 端口
- 不是 Real Atom 主动连接的地址

**Real Atom 的 devinfo.station**：
- station 是 Real Atom 需要管理的设备配置
- 但 Real Atom 不主动连接 station
- Real Atom 通过 ping 判断设备是否在线

**streamsrc 和 station 是不同概念**：
- streamsrc: Real Atom 监听的数据接收端口
- station: Real Atom 管理的设备列表（通过 ping 监控状态）

## ISSUE-003: Real Atom 不主动连接 station

### 问题描述
即使 devinfo 中配置了 station，Real Atom 也不主动连接。

### 现象
```
Real Atom 启动 → 监听 streamsrc 端口 (18012) → 等待设备连接
                                            ↓
                          不主动连接 devinfo.station 指定的地址
```

### Real Atom 连接判断方式
Real Atom 通过 **ping** 判断设备是否在线：
- ping 通 → m_bIsConnected = 1
- ping 不通 → m_bIsConnected = 0（持续重试）

### 测试结果
- Real Atom streamsrc 端口 (18012) **接受连接**
- Mock Device 连接 streamsrc 端口成功
- 但 Real Atom 没有主动连接 Mock Device (9000)

## ISSUE-004: 端口绑定模式冲突

### 问题描述
Real Atom 和 Mock Device 都试图绑定端口导致冲突。

### 现象
当 streamsrc port 非空时（如 9000）：
```
AtomSvcV3.exe → 绑定 0.0.0.0:9000 (监听模式)
Mock Device → 绑定 127.0.0.1:9000 (监听模式)
端口冲突！
```

### 解决尝试
将 streamsrc port 设为空：
```xml
<streamsrc ip="127.0.0.1" port="" />
```
结果：Real Atom 随机分配 streamsrc 端口（如 18012），避免冲突。

## 测试链路分析

### 架构图

```
┌─────────────┐     SOAP/HTTP      ┌─────────────┐
│  Proxy-B   │ ──────────────────→│  Real Atom  │
│   :8081    │                   │   :8282     │
└─────────────┘                   └─────────────┘
                                            │
                                            │ streamsrc
                                            ↓ (监听 18012)
                                    ┌─────────────────┐
                                    │  Mock Device    │
                                    │  (应作为客户端) │
                                    └─────────────────┘
```

### 问题
1. Mock Device 当前是**服务器模式**（监听 9000）
2. Real Atom 是**服务器模式**（监听 streamsrc 端口）
3. 两者无法建立连接

### 正确模式应该是
- Mock Device 作为客户端，连接 Real Atom 的 streamsrc 端口
- 按 RMCPTP 协议发送设备注册/心跳
- Real Atom 收到后处理业务请求

## SOAP 请求格式对比

### YL_workspace 原始请求（B_SglFreqMeas）
```xml
<?xml version="1.0" encoding="UTF-8"?>
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                 xmlns:srrc="http://www.srrc.org.cn">
  <soapenv:Body>
    <srrc:requestbody>
      <srrc:userid>RX_admin</srrc:userid>
      <srrc:appid>123456</srrc:appid>
      <srrc:executetime>0</srrc:executetime>
      <srrc:priority>9</srrc:priority>
      <srrc:mfid>53090001140007</srrc:mfid>
      <srrc:equid>8f1b953d-d618-4d4f-a106-81c47183af3c</srrc:equid>
      <srrc:equpara>
        <srrc:items>
          <srrc:item>
            <srrc:paraname>frequency</srrc:paraname>
            <srrc:paravalue>100000000</srrc:paravalue>
          </srrc:item>
          <srrc:item>
            <srrc:paraname>ifbw</srrc:paraname>
            <srrc:paravalue>40000000</srrc:paravalue>
          </srrc:item>
          <!-- ... 更多参数 ... -->
        </srrc:items>
      </srrc:equpara>
      <srrc:resulttype>
        <ITU/>
        <audio/>
      </srrc:resulttype>
    </srrc:requestbody>
  </soapenv:Body>
</soapenv:Envelope>
```

### 关键字段说明

| 字段 | YL 值 | 说明 |
|------|-------|------|
| mfid | 53090001140007 | 制造商标识 |
| equid | 8f1b953d-d618-4d4f-a106-81c47183af3c | **设备GUID，不是 station id** |
| paraname | frequency, ifbw, gain... | 参数名 |
| resulttype | `<ITU/><audio/>` | 结果类型 |

### 重要发现
equid 是设备的 **GUID**（如 `8f1b953d-d618-4d4f-a106-81c47183af3c`），不是 station id（如 `53090006`）。
