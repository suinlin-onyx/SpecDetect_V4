## 一、streamsrc 帧格式概述

streamsrc 是 Atom 设备主动推送频谱数据的通道，使用独立的私有协议。

### 帧类型

| 帧类型 | 大小 | 说明 |
|--------|------|------|
| FSCAN-529 | 1086 字节 | 512 点频谱数据 (band1/band2) |
| FSCAN-434 | 896 字节 | 417 点频谱数据 (band3) |

### 帧结构 (offset from frame start)

```
偏移 0-3:   Sync (0xEEEEEEEE)
偏移 4-5:   VER (大端序, 值=256)
偏移 6-9:   STC (同步通道号)
偏移 10-17: TS (时间戳)
偏移 18-19: Indicator (0x0068=FSCAN-434, 0x0064=FSCAN-529?)
偏移 20-23: Type (0x03000000=FSCAN-434)
偏移 24:    DT (数据类型, 0x0C=FSCAN)
偏移 25-28: DL (payload长度, little-endian)
偏移 29-61: Private Metadata (33 bytes)
偏移 62+:   Spectrum Data (交替字节模式: dBm, 0xFF, dBm, 0xFF...)
```

## 二、Private Metadata 字段分析

### 2.1 确认的字段 (多帧验证)

| 偏移 (frame) | 大小 | 字段名 | 验证方法 |
|--------------|------|--------|----------|
| 29 | 1 | 频段序号 | 多帧对比，529=0x01, 434=0x01 |
| 50-51 | 2 | 起始频率序号 (little-endian) | Band1=0, Band2=512, Band3=1024 |
| 58-59 | 2 | 帧信道数量 | 529=512, 434=417，多帧确认 |

### 2.2 固定值字段 (需进一步验证)

| 偏移 (frame) | 大小 | 当前值 | 说明 |
|--------------|------|--------|------|
| 30 | 1 | 0xA1 | 多帧不变，可能为固定标记 |
| 31-34 | 4 | 0x00000500 (529) / 0x00000400 (434) | 与帧信道数量相关 |
| 35-38 | 4 | 浮点数 | 固定值 |
| 43-46 | 4 | 浮点数 | 固定值 |
| 47-50 | 4 | 浮点数 | 固定值 |
| 51-54 | 4 | 浮点数 | 固定值 |
| 59-62 | 4 | 浮点数 | 固定值 |

### 2.3 当前 private_metadata_434 硬编码值 (已修正)

```python
private_metadata_434 = bytes([
    0x01, 0xa1, 0x05, 0x00, 0x00, 0x00, 0x00, 0x00,  # 0-7
    0x80, 0xe8, 0x54, 0xa0, 0x41, 0x00, 0x00, 0x00,  # 8-15
    0x30, 0xc5, 0xda, 0xa1, 0x41, 0x00, 0x04, 0x00,  # 16-23 (pm[22]=0x04 -> start_index)
    0x00, 0x00, 0x50, 0xc3, 0x46, 0xa1, 0x01, 0x00,  # 24-31
    0x00                                           # 32
])
```

### 2.4 关键字段解析验证

```
frame[29] = pm[0]  = 0x01           -> 频段序号 = 1
frame[50:52]       = pm[21:23]      = 0x00, 0x04 = 0x0400 = 1024 (little-endian) ✓
frame[58:60]       = pm[29:31]      = 0xA1, 0x01 = 0x01A1 = 417 (little-endian) ✓
```

**重要修正 (2026-04-18):**
- 之前错误地认为 start_index 在 frame[60:62]
- 实际 start_index 在 frame[50:52] (little-endian uint16)
- Band1: frame[50:52] = 0x0000 = 0
- Band2: frame[50:52] = 0x0200 = 512
- Band3: frame[50:52] = 0x0400 = 1024

## 三、频段与帧类型映射

### 扫描周期
设备按 529→529→434 循环推送，对应：
- Band1: 512点, 起始序号 0, 频率 137.0-149.775MHz
- Band2: 512点, 起始序号 512, 频率 149.8-162.575MHz
- Band3: 417点, 起始序号 1024, 频率 162.6-173.0MHz

### 帧大小与数据类型

| 帧类型 | 总大小 | Spectrum大小 | DL值 | 帧信道数量 |
|--------|--------|--------------|------|-----------|
| FSCAN-529 | 1086 | 1024 (512×2) | 1057 | 512 |
| FSCAN-434 | 896 | 834 (417×2) | 867 | 417 |

### 频率计算公式

```
实际频率 = 起始频率 + 起始序号 × 步长
其中: 步长 = 25kHz = 0.025MHz

示例:
- Band3: 137 + 1024 × 0.025 = 162.6MHz ✓
```

## 四、验证方法总结

### 4.1 多帧对比法

1. **同一类型的多个帧对比**
   - 帧头固定字段应完全一致
   - 帧头中的计数器字段应有规律变化
   - 数据部分随时间变化

2. **不同类型帧对比**
   - FSCAN-529 vs FSCAN-434 对比
   - 找出差异字段，确定字段含义

3. **计算验证**
   - 用解析出的字段值计算频率
   - 与测试工具显示的频率对比

## 五、关键发现与问题

### 5.1 测试工具解析位置

测试工具从以下位置读取字段：
- `frame[29]` = 频段序号
- `frame[58:60]` = 帧信道数量
- `frame[60:62]` = 起始频率序号

### 5.2 当前问题 - 已解决

**问题1：434帧 metadata 编码错误 - 已解决**
- 根因：start_index 编码位置错误，之前认为在 frame[60:62]
- 实际：start_index 在 frame[50:52] (little-endian uint16)
- 修复：position 22 从 0x00 改为 0x04
- 验证：frame[50:52] = 0x0400 = 1024 ✓

**问题2：metadata 结构 - 已澄清**
- 测试工具可能读取不同版本或有其他解析逻辑
- 真实设备 434 帧中 frame[60:62] = 0，实际 start_index 在 frame[50:52]

**问题3：529帧 band1/band2 区分 - 已确认**
- 真实设备 529 帧中 band2 的 start_index=512 在 frame[50:52]
- 我们的 529 metadata position 22 = 0x02 已正确

### 5.3 待深入分析

1. **验证修复后的 emulated_atom**
   - 需要用测试工具验证 434 帧 now正确显示 start_index=1024

2. **官方协议文档**
   - 当前所有分析都是逆向得出
   - 建议联系设备厂商获取 streamsrc 协议规范
