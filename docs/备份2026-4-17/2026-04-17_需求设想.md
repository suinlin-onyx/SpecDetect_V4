## 1. 背景

### 1.1 现有设计局限

当前设计的原子服务是**单链路**模式：
- 只有一个固定的Streaming端口（18012）
- 同一时刻只能有一个设备连接
- 无法支持多设备并发连接和数据分发

### 1.2 实际需求

Atom服务本身具备多路转发能力，需要在复现设计中释放这一能力。

## 2. 多端口监听设计

### 2.1 端口配置方式

在预设文件中预设多个监听端口：

```xml
<!-- 设备预设 XML -->
<device>
    <id>53090001140012</id>
    <streaming_ports>
        <port>18010</port>
        <port>18011</port>
        <port>18012</port>
    </streaming_ports>
</device>
```

### 2.2 端口匹配与建连

- 远端设备请求时携带端口信息
- Atom根据请求端口匹配预设配置
- 端口匹配成功则建立长连接
- 不匹配则拒绝连接

### 2.3 持久端口监听

Atom服务启动时，同时监听预设中的所有端口：
- 18010、18011、18012...并行监听
- 每个端口独立接受连接请求

## 3. 线程池管理设计

### 3.1 线程池架构

```
┌─────────────────────────────────────────────────────────────┐
│                    Atom Service                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │              持久线程池 (ThreadPool)                    │  │
│  │                                                       │  │
│  │   ┌─────────┐  ┌─────────┐  ┌─────────┐             │  │
│  │   │Worker 1 │  │Worker 2 │  │Worker N │             │  │
│  │   │(18010)  │  │(18011)  │  │(18012)  │             │  │
│  │   └────┬────┘  └────┬────┘  └────┬────┘             │  │
│  │        │             │             │                   │  │
│  │        └─────────────┴─────────────┘                   │  │
│  │                      │                                   │  │
│  │              ┌───────┴───────┐                          │  │
│  │              │  数据分发层    │                          │  │
│  │              └───────────────┘                          │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 线程生命周期管理

两种管理方式可结合使用：

| 管理方式 | 说明 |
|----------|------|
| **子线程自管理** | 工作线程独立运行，通过Socket连接状态自管理 |
| **WebSocket命令触发** | 通过WebSocket发送命令控制子线程启停 |

```python
# 示例：线程生命周期管理
class WorkerThread:
    def __init__(self, port, socket):
        self.port = port
        self.socket = socket
        self.running = True

    def stop(self):
        self.running = False
        self.socket.close()

# WebSocket命令接口
@app.websocket('/control')
async def control(ws):
    while True:
        msg = await ws.receive()
        if msg['action'] == 'stop':
            worker_manager.stop_worker(msg['port'])
```

### 3.3 长连接保活

- 持久线程池保证工作线程常驻
- Socket心跳检测保活连接
- 断线自动重连机制

## 4. 连接生命周期管理

### 4.1 问题场景

Atom作为中间件需要维持两端的长连接：

```
请求侧（Client）◄───────► Atom ◄───────► 设备侧（Device）
```

**问题**：
- 请求侧可能主动中断或网络原因断连
- 如果请求侧连接中断，对应的设备侧连接也应切断
- 但一个设备侧连接可能对应多个请求侧连接（一对多）
- **只有所有请求侧连接都中断后，才能中断设备侧连接**

### 4.2 方案：引用计数（Reference Counting）

```
设备侧连接（1个）
      ▲
      │  ref_count = N
      │
      │      ┌─────────┐
      └──────│ Clients │  N个请求侧连接
             └─────────┘
```

**核心逻辑**：
| 操作 | 引用计数 | 结果 |
|------|----------|------|
| 请求侧连接建立 | ref_count +1 | 设备侧连接复用或新建 |
| 请求侧连接断开 | ref_count -1 | 暂不断开设备连接 |
| ref_count = 0 | 断开设备侧 | 清理所有资源 |

### 4.3 数据结构设计

```python
class ConnectionMapping:
    """连接映射管理器"""
    def __init__(self):
        # device_id -> DeviceConnection
        self.device_connections: dict[str, DeviceConnection] = {}
        # client_id -> device_id 映射
        self.client_to_device: dict[str, str] = {}

    def register_client(self, client_id: str, device_id: str) -> int:
        """注册客户端到设备的连接，返回当前引用计数"""
        if device_id not in self.device_connections:
            self.device_connections[device_id] = DeviceConnection(device_id)
        device_conn = self.device_connections[device_id]
        device_conn.ref_count += 1
        self.client_to_device[client_id] = device_id
        return device_conn.ref_count

    def unregister_client(self, client_id: str) -> int:
        """注销客户端连接，返回剩余引用计数"""
        device_id = self.client_to_device.pop(client_id, None)
        if device_id and device_id in self.device_connections:
            device_conn = self.device_connections[device_id]
            device_conn.ref_count -= 1
            if device_conn.ref_count <= 0:
                device_conn.close()  # 断开设备连接
                del self.device_connections[device_id]
            return device_conn.ref_count
        return 0

class DeviceConnection:
    """设备侧连接"""
    def __init__(self, device_id: str):
        self.device_id = device_id
        self.ref_count = 0
        self.socket = None  # RMCPTP socket
        self.clients = []   # 注册的客户端列表

    def close(self):
        if self.socket:
            self.socket.close()
            self.socket = None
```

### 4.4 生命周期流程

```
┌─────────────────────────────────────────────────────────────┐
│ 场景1：Client A、B 连接同一 Device                            │
├─────────────────────────────────────────────────────────────┤
│ 1. Client A 连接 → ref_count=1 → 建立 Device 连接          │
│ 2. Client B 连接 → ref_count=2 → 复用 Device 连接          │
│ 3. Client A 断开 → ref_count=1 → Device 连接保持            │
│ 4. Client B 断开 → ref_count=0 → 关闭 Device 连接           │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 场景2：Client A 连接 Device后断开重连                        │
├─────────────────────────────────────────────────────────────┤
│ 1. Client A 连接 → ref_count=1 → 建立 Device 连接          │
│ 2. Client A 断开 → ref_count=0 → 关闭 Device 连接          │
│ 3. Client A 重连 → ref_count=1 → 重建 Device 连接          │
└─────────────────────────────────────────────────────────────┘
```

### 4.5 异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 请求侧异常断线 | 心跳检测超时 → 自动触发 unregister |
| 设备侧异常断线 | 通知所有注册客户端 → 清理映射 |
| 网络闪断 | 短时重连保护窗口 → 恢复连接 |

### 4.6 与线程池的配合

工作线程不再直接管理Socket生命周期，而是通过 ConnectionMapping 管理：

```
Worker Thread
    │
    ├── register_client(client_id, device_id)
    │       └── 告知 ConnectionMapping 记录引用
    │
    ├── receive_data(data)
    │       └── 通过 DataDispatcher 分发给所有注册客户端
    │
    └── on_client_disconnect(client_id)
            └── unregister_client(client_id)
                    └── ConnectionMapping 判断是否断开设备连接
```

## 5. 数据分发设计

### 5.1 一对多分发

Atom收到的设备数据流可以同时分发给多个WebSocket连接：

```
Device ──RMCPTP──► Atom ──┬──► WebSocket 1 (18010)
                          ├──► WebSocket 2 (18011)
                          └──► WebSocket 3 (18012)
```

### 5.2 分发策略

| 策略 | 说明 |
|------|------|
| **端口绑定** | 数据按端口配置分发到对应连接 |
| **广播** | 同一数据分发给所有已连接客户端 |
| **订阅** | 客户端订阅特定数据类型/频段 |

### 5.3 分发实现

```python
class DataDispatcher:
    def __init__(self):
        self.subscribers = {}  # port -> [websocket connections]

    def dispatch(self, data, source_port):
        # 端口绑定分发
        if source_port in self.subscribers:
            for ws in self.subscribers[source_port]:
                await ws.send(data)

    def subscribe(self, port, ws):
        self.subscribers.setdefault(port, []).append(ws)

    def unsubscribe(self, port, ws):
        if port in self.subscribers:
            self.subscribers[port].remove(ws)
```
