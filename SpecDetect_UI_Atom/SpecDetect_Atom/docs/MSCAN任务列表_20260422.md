## 关键发现

### TCP 粘包问题

帧19数据（274字节）实际包含多个 SGLFREQ 帧：
```
offset 11: 帧1开始 (dw_length=31)
offset 60: 帧2开始
offset 91: 帧3开始
...
```

每个 SGLFREQ 帧：18 (header) + 31 (payload) = 49 字节

### 问题原因

`receive_responses` 从 offset 0 解析，得到错误的 `dw_length=256`，导致：
1. 把多个帧当作一个帧处理
2. 剩余数据中的真正 SGLFREQ 帧被错过
